Prompt (so übernimmst du ihn in 1.3):

For a student project (team of 3–4, one semester), we are building a meeting assistant web app that records meetings (in person or online), transcribes them, and generates summaries for the users. How would you check that the system works as intended?

Antwort der KI:

Unit tests for the backend logic and API endpoints, run automatically in a CI pipeline on every merge request.
Integration test of the whole pipeline (upload → transcription → summary) using a short, fixed audio file, so you can see whether all components work together.
Test corpus for transcription quality: a few recordings with hand-written reference transcripts. Measure the word error rate (WER) and set a target value. "Perfect" transcription is not realistic, so the goal has to be measurable.
Check the summaries manually: they cannot be tested reliably by automation. People rate them against the transcript, and each point in the summary links to the transcript passage it is based on, so invented content is easy to spot.
End-to-end tests of the main user flow: log in, record or upload, view the result.
Usability tests with people outside the team who click through the app.
Staging environment to test the system under realistic conditions before release.
